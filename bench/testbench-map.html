The six levels, and where each one runs

Each level only means something once the one before it passes: there's no point building code that doesn't parse, or testing a node that doesn't build. Where a level runs is set by what it needs.

On the lab box: exactly what happens

To run on the box, the bench needs a copy of the repo there. The two existing folders hold the only known-good builds and your uncommitted captures, so the bench gets its own scratch folder, ~/bench_work. It's a new, empty folder I'd create, not old code. Deleting it undoes everything.

/home/rcp2026/ ├── rcp-desktop/ untouched · realman_manip · the build the 25 Aug session ran ├── rcp-github/…/Renaissance-Capstone-Project/ untouched · = main · read once, to copy from └── bench_work/ NEW · everything the bench writes lives here ├── gappler/ copy of main + the bench commits ├── build/ install/ log/ only after you OK the build (step 3) └── reports/ preflight output, kept for the docs /home/iot22/ locked to rcp2026 · reading needs your sudo password
Step 1

Make the scratch copy

needs your OK
Commands
mkdir ~/bench_work
git clone ~/rcp-github/Renaissance-Capstone-Project ~/bench_work/gappler   # local copy, shares files on disk
cd ~/bench_work/gappler && git pull git@github.com:dionyichia/Gappler.git main   # adds bench/ + docs/
Writes
Only ~/bench_work/gappler. A local clone reuses git's files, so it costs about the size of the checkout, not the 3 GB history. [inferred]
Reads
rcp-github's git history. Cloning never modifies the source.
Step 2

Run preflight, static and contracts

needs your OK
Commands
cd ~/bench_work/gappler && source /opt/ros/humble/setup.bash
./bench/run.sh | tee ~/bench_work/reports/preflight-2026-09-11.txt
Does
Looks: lists interfaces, pings the arm and LiDAR addresses, opens a TCP connection to the arm's port and closes it, reads topic rates if something is already running. Sends no command.
Writes
One report file. I'll first add a --repo option so it can inspect rcp-github's model files (3.7 GB, not in git) in place instead of copying them.
Step 3

Build (Tier 2)

waiting on you
Commands
source /opt/ros/humble/setup.bash          # nothing else: a stale overlay poisons the build
colcon build --base-paths ros2_robot_ws/src deps_ws/src \
  --build-base ~/bench_work/build --install-base ~/bench_work/install
Does
Compiles C++ and packages Python: the same thing the earlier team did to make install/. About 6 min for the arm's 24 packages [reported]. Keeps the CPU busy while it runs, so pick a time when nobody is operating the robot.
Doesn't
Start any node, contact the arm or LiDAR, use sudo, install packages, or touch the existing install/ folders.
Writes
~/bench_work/build, install, log: a few GB [inferred]; 33 GB free. Livox needs its missing package.xml copied into the scratch copy first.
Step 4

Node tests (Tier 3)

later
Isolation
A private ROS channel (ROS_DOMAIN_ID=77). iot22 is logged in on the same machine, and localhost-only does not separate the two users, so the unique channel is what isolates. Each test checks the channel is empty before starting.
Never
Starts rm_driver. The state-machine test runs against a simulated arm and refuses to start if the real driver's topics exist.

Never tested by the bench

By design. Each of these needs a person at the robot with the e-stop, and none has ever been run end to end.

Arm motionThe state machine homes the arm within seconds of launch, to a pose nobody has validated.
GripperOpening or closing it is a physical command.
Driving the basePublishing /goal_pose or /cmd_vel moves the robot.
The whole pipelineVoice → SAM 3 → gaze → grasp is cut in the code today, so there is no end-to-end path yet.
