E-stop delivery (W3, Tier 3)

finds a real bug
Command
./bench/estop_delivery.sh   # private channel 77, refuses if rm_driver exists
Result
Keys E, R and S deliver their messages. After kill -INT, the stop arrived 5 of 5 times (the audit expected it might not), but the script then crashes on exit.
Found
Pressing Ctrl+C in the e-stop terminal does nothing: the terminal is in raw mode, so it arrives as a plain character. No stop, no exit (CODE_AUDIT B2a).
Done

Never tested by the bench

By design. Each of these needs a person at the robot with the e-stop, and none has ever been run end to end.

Arm motionThe state machine homes the arm within seconds of launch, to a pose nobody has validated.
GripperOpening or closing it is a physical command.
Driving the basePublishing /goal_pose or /cmd_vel moves the robot.
The whole pipelineVoice → SAM 3 → gaze → grasp is cut in the code today, so there is no end-to-end path yet.
