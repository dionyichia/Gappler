# T2.19 to T2.21 plan: time glasses data by when it was captured

**Goal:** the aria client should pick the gaze and the glasses image from the moment you spoke,
using the glasses' own capture times, instead of guessing delays with knobs. Why, and the review
behind it: `T2.9_TIMING_REVIEW.md` sections 9.1 to 9.10. Tasks: T2.19, T2.20, T2.21 in
`docs/task-tree.html`.

**Status (2026-10-17):** planned, decisions below are Dion's. Nothing built. PR #76 (T2.9) is not
merged yet, so this work branches from it.

## 1. Decisions already made (Dion, 2026-10-17)

| # | Decision | Why |
|---|---|---|
| 1 | **Two PRs.** PR A is T2.19 + T2.20. PR B is T2.21 | PR A can be fully tested on the existing replay. PR B needs a new recording |
| 2 | **Stamp with glasses time** (device `capture_timestamp_ns`), not computer time | The pose pipeline already does (`pose_streaming_pipeline.py:266-271`, `:290`). Word, gaze and image share the glasses clock. Converting to computer time waits until glasses data meets robot data (T8.5) |
| 3 | **Start now**, before the live image and gaze rates are measured (T2.15) | Code must work at any rate: history bounded by time, not count. Tune values after the live rates are known |
| 4 | **The vote replaces the 1 s mean.** `mean_gaze` goes | One rule, not two |
| 5 | **Gaze is the bridge between clocks in PR A.** Gaze samples are selected by arrival time (word arrival minus `speech_latency_s`, `gaze_window_s` wide), as today. Their glasses stamps then choose the image | No clock offset to estimate. Error stays the eye pipeline's own delay, as today. T2.21 replaces the arrival-time step |
| 6 | **Keep a bounded wait for the matching image, renamed** `image_wait_s` to `matching_image_wait_s` (3 s) | On the box images arrive 1 to 3 s late, so the image from when you spoke may not be there yet when the word comes |
| 7 | **No gaze, or no clear vote: ask the user** (T2.18). Until T2.18 exists, the word alone stands, as today | The best SAM 3 score was the wrong box on recording c2cbafe8 |
| 8 | **Users hold their gaze on the object while speaking.** Look first, then speak is a stretch goal | Keeps the window simple |
| 9 | **T2.21 is tested on a new recording** Dion makes (look at the box, say "pick up the box" a few times). It must not block PR A | The current recording has no spoken commands on the same clock as its images |

## 3. PR A: T2.19 + T2.20

**Branch:** `t2.19-glasses-capture-timestamps`, from `t2.9-aria-detection-on-recording`. Once PR #76
is merged into `dev`, merge `origin/dev` into this branch (never rebase). **PR title:**
`T2.19, T2.20: glasses capture timestamps, image history and gaze vote`, into `dev`.

Build in these steps. Each step ends with something that can be checked.

### Step 1. Carry the capture time to the workers (T2.19)

- `image_streaming_pipeline.py:226-232`: put `(image, record.capture_timestamp_ns)` on the queues,
  as `pose_streaming_pipeline.py:290` does. `rgb_worker` and `et_worker` unpack it.
- `aria/tools/replay_recording_to_glasses_topics.py:80` (and the start-up frames at `:61`): pass the
  recorded device time with each frame. The VRS record has it.
- `playback_controller.py`: check whether it feeds the same workers. If it does, same change.
- **Check:** the replay runs on the Mac to the point where it would publish (or a unit test of the
  queue item shape).

### Step 2. Publish with the capture time (T2.19)

- Images: stamp `header.stamp` with the capture time. Today `ros_publisher.py:33` stamps with the
  computer's time at publish. Give `publish_image` an optional stamp, so other callers keep working.
  This covers `/aria/rgb_camera/undistorted` and the raw eye image `et_worker` publishes.
- Gaze: `geometry_msgs/Point` becomes `geometry_msgs/PointStamped`, stamped with the eye frame's
  capture time (`image_streaming_pipeline.py:199-200`).
- Update every gaze reader: `aria_segmentation_client.py:75`, `visualizer/ros_manager.py:79`,
  `object_recognition/object_recognition_pipeline.py:159`. Check `visualizer.py:176-181` too.
- Contract: `docs/CHANNEL_CONTRACT.md` gaze row, then `python3 bench/contracts.py snapshot` after
  Dion agrees the contract change. Wiring map gaze row.
- **Check:** bench L0 to L2 on the Mac. On the box, with Dion's yes: replay plus
  `ros2 topic echo` shows glasses-time stamps on both topics.

### Step 3. The vote (T2.20, no ROS)

- `gaze_pick.py`: replace `mean_gaze` with a vote. For each gaze sample, `pick_mask` gives its mask
  (or none). The mask with the most samples wins, if it holds at least a minimum share of them.
  Return the winner, its share, and the distance, so the log can show them.
- Update `test_gaze_pick.py`: a test where the mean of two fixations lands on neither mask but the
  vote picks the one looked at longer. A test where no mask reaches the minimum share.
- Update `aria/tools/replay_recording_gaze_pick.py` stage 4 to use the vote.
- **Check, the acceptance test:** stage 4 on recording c2cbafe8 must still pick the box in at least
  60 of 61 frames (`T2.9_GAZE_PICK_ON_RECORDING.md` finding 4). Run on the Mac with the `~/aria-test`
  venv and the stage 3 masks already saved next to the recording.
- **Values go to Dion:** the minimum share, and how close in time a gaze sample must be to the
  image to count (head motion, review 9.10 point 1). Propose them from a sweep on c2cbafe8, then ask.

### Step 4. Image history and the clock bridge (T2.20)

In `aria_segmentation_client.py`:

1. Keep about 20 s of glasses images (the `CompressedImage` messages, not decoded) with their
   stamps, and gaze as `(arrival time, glasses time, x, y)`. Bound both by time. Decode only the
   image that is used.
2. On a word: select gaze by arrival time, ending `speech_latency_s` before the word's arrival
   (`self.word_at`), `gaze_window_s` wide. This is the same window as today.
3. Take those samples' glasses stamps. Pick the image whose capture time is nearest them.
4. If no image captured at or after the window's start has arrived yet, wait up to
   `matching_image_wait_s` for one, then pick again. Rename the knob in `aria_config.yaml` and the
   docs that name it.
5. Vote with the gaze samples close in glasses time to that image (step 3's rule).
6. Delete what this replaces: the "newest image only" logic, the old age check, `self.wait_until`
   if it is no longer needed.

- Keep: the word goes out at once, the grasp request at once, the word counter that drops stale
  replies, the reference Target. Changing the order is T8.5's job.
- Update `test_aria_segmentation_client.py`. The helper `look()` must give stamped gaze and images.
  Tests to have: the image from the gaze window is chosen over a newer one, the wait for a matching
  image, a late reply after a new word is still dropped, no gaze sends the word alone.
- **Check:** client tests on the box (with Dion's yes), then the e2e replay
  `docs/dion_docs/t2.9_e2e_replay_on_box.sh`. Pass: 4 of 4 words send a reference, and the log
  shows which image and how many gaze samples were used. Save the run in `docs/bench-runs/`.

## 4. PR B: T2.21, the stamped word (later)

**Branch:** `t2.21-stamped-spoken-word`, after PR A. Not started until Dion has the recording
(decision 9). The outline, details to agree with Dion first:

1. `AudioObserver.on_audio_received` (`audio_streaming_client_observer.py:51`) keeps
   `record.capture_timestamps_ns` (one per sample, checked in the SDK on the Mac 2026-10-17) next to
   the audio in its ring buffer. `snapshot()` returns both.
2. `audio_worker` uses those times instead of "the buffer ends now"
   (`audio_streaming_pipeline.py:174-175`). It finds the object word in Whisper's word times
   (`word_timestamps=True`, `:135`), or falls back to the sentence span if the LLM's word is not in
   the transcript.
3. Publish the word with its time on a new stamped topic. Keep `/aria/audio/prompt` (`String`) for
   the nav nodes.
4. The client uses the word's glasses time directly. `speech_latency_s` and the arrival-time step
   from decision 5 go.
5. The replay plays the recording's audio into `audio_worker` on the same clock as its images.
