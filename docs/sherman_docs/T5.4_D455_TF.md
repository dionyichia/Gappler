## Objective

Determine the transform chain from `robot_base_link` to the D455 optical frames,
recording every input with provenance and leaving the one unmeasurable link
explicitly open. No live TF publisher is created here: CAD-only numbers must never
become runtime transforms before the mount is fitted (T5.3) and taped (T5.4).

The vendor model's `rw_Joint` / `lw_Joint` origins are
`(0, ±0.13379, 0.065) m` relative to `robot_base_link`
(`nav/vendor/urdf/xpkg_urdf_echo_plus/urdf/model.urdf:90-94,143-147`). With the
reported axle height 65 mm and axle aligned to the measured chassis midpoint,
the model origin is at floor height: `65 − 65 = 0 mm`.

Therefore the **provisional parent-to-bottom-screw transform** is:

```text
robot_base_link → D455 bottom mounting-screw frame
x = 195 + 13 = 208 mm
y = 0 mm
z = 558 − 30 − (65 − 65) = 528 mm
xyz = (0.208, 0, 0.528) m
rpy = (0, 0, 0) rad  [visual estimate only]
```

This is not `camera_link` or an optical-frame transform. Apply the package's
socket-to-sensor chain separately, after confirming the installed package and
frame naming. No runtime TF has been changed. Geometry accuracy and alignment
are not calibrated; T5.5 camera–LiDAR calibration remains separate.

## Package facts `[code]` (`realsense2_description/urdf/_d455.urdf.xacro`, IntelRealSense/realsense-ros)

- Origin = bottom screw mount: user `<origin>` attaches parent → `bottom_screw_frame`;
  `camera_link` floats off it by (+0.0158, +0.0475, +0.0145) m.
- Body 0.124 × 0.029 × 0.026 m; nominal sensor offsets off `camera_link`:
  depth +0, right-IR y −0.095 (95 mm baseline), color y −0.059; IMU at
  (−0.01602, −0.03022, +0.0074).
- Optical frames hang off each sensor via fixed `rpy(−π/2, 0, −π/2)` (axis
  convention flip, never measured).
- Header comment: values approximate; the driver overwrites fine extrinsics live
  from factory calibration. Depth start plane: datasheet Rev 009, Fig 4-4
  (`zero_depth_to_glass` 4.55 mm).
- Responsibility split: user tapes mount→socket; Intel owns socket→sensors;
  driver owns live fine extrinsics.

## Chain derivation `[inferred]`

```
robot_base_link --(UNKNOWN: platform↔base placement)--> platform edge
  --(+13.05, 0, −29.50 mm, CAD)--> socket ≈ camera_link (via package offsets)
  --(package, then driver live)--> color/depth frames --> optical frames (fixed rpy)
```

At the 2026-09-24 session, final numeric TF was **not computable until the UNKNOWN closes** (platform↔base needs
either full-assembly CAD positioning or the October tape). No placeholder numbers
are entered anywhere in this record or any launch file.

The 2026-10-06 as-fitted measurements above now provisionally close that physical
placement gap. The CAD derivation remains historical evidence, not a live TF.

## Shared-geometry implementation, 2026-10-06

`shared/global_config.yaml` now has separately named `geometry` entries for
`arm_mount`, `lidar_mount` and `d455_bottom_screw`. `gappler_common.static_transform_args`
validates finite xyz/rpy triples and frame names, then converts roll/pitch/yaw to
the existing static publisher's positional yaw/pitch/roll order.

Both SLAM launch files read the arm and LiDAR entries. Their numerical behavior
is retained, including the existing arm yaw `3.14159`. The D455 screw entry is
stored only, not published or incorrectly substituted for an optical frame.

Object approach and return-to-user read **separate legacy references**, each
still 0.18 m. The approach marker uses the shared arm height. These legacy
references are not claimed as measured camera/sensor or robot-front positions;
Dion's intended physical references must be settled before behavior changes.

The stdlib contract scanner resolves the config's JSON flow mappings (valid YAML)
without executing launch code. The existing static TF contracts remain visible;
the baseline was not reset. `bench/test_geometry.py` covers shared wiring,
preserved values, angle ordering, config propagation and invalid inputs. Runtime
checks require existing PyYAML and are explicitly skipped where it is absent.

## Flags and residuals

Verification of this implementation:
- Mac `./bench/run.sh quick`: static, geometry wiring, memory-graph tests and
  contracts PASS; geometry runtime SKIPPED (PyYAML absent), L3–L6 skipped.
- Lab-box candidate files in an isolated verification directory: six geometry
  tests PASS, including four runtime tests using installed PyYAML.
- Mock navigation bench, empty domain 174 + localhost-only: six controls PASS,
  four pre-existing XFAIL (F1/F2/E1). No real navigation/base driver launched.
- Isolated static publishers constructed from the shared helper, empty domain
  175 + localhost-only: arm `(0.18, 0, 0.48)`, yaw 3.14159; LiDAR
  `(0.18, 0, 0.2)`, yaw 0; provisional screw `(0.208, 0, 0.528)`, yaw 0.
  TF lookups matched; all verification publishers stopped afterward. This does
  not integrate the RealSense sensor chain or measure physical alignment.
- Full SLAM launches were not executed: they start real base drivers and flush
  network addresses. No autonomous full hardware launch is permitted.

- **Frame-name collision:** the wrist D435i publishes identical frame names. The D455
  bring-up needs `/base_camera` namespacing + remap decision (Dion, T5.5) before any
  publisher exists.
- **"Higher" requirement:** resolved in T5.2 v2 (higher view for navigation);
  Sherman confirmed navigation-view suitability during T5.3.
- **Task remains OPEN:** shared fixed mounts and isolated box checks are implemented,
  but D455 package/frame-chain integration and
  approach/return-reference decisions remain. The screw x=0.208 m is not a
  blanket replacement for existing 0.18 m constants. Wrist-camera geometry is
  separate; no navigation-reference behavior change is made here.
- **October taping list (T5.4, after T5.3 fit):** platform edge → base center (x/y),
  platform-top → chassis-top (z), camera pitch/roll/yaw, socket method note, D455
  serial + cable route. The 95 mm baseline recompute and the 0.48 segment-sum are the
  on-the-spot acceptance checks.
- **Axle anchors (origin location):** wheel axle centers (0, ±0.13379, 0.065) taped
  to chassis faces + floor in the same visit; locates `robot_base_link` physically.
