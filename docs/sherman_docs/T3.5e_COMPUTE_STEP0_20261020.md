## GPU use by the mapper

- No CUDA or GPU reference anywhere in the pinned mapper: grep for `cuda|nvcc|gpu|opencl|cv::cuda|__global__` over
  `fast_livo/CMakeLists.txt`, `fast_livo/src`, `fast_livo/include` and `rpg_vikit` returned nothing. The mapper is CPU only. `[code]`
- The local source copy matches the box's `pinned-src`: `LIVMapper.cpp` and `vio.cpp` have identical sha256 on the Mac copy and in
  `t35c-combined-build.LKf0QQ/pinned-src`. The other files were not hashed. Pin: `U-AMC/FAST-LIVO2-ROS2` commit `a09599a`
  (`recipe/build_inside.sh:57`). `[measured]` for the two hashes, `[code]` for the pin.
- The container script gives the mapper no GPU (`t35d_probe_container.sh` has no `--gpus`). `[code]`

## Thread count

- `CMakeLists.txt:47-59`: `ProcessorCount(N)`; if N > 4 the macro `MP_PROC_NUM` is 4, else N when N > 1, else 1. It is a build-time value. `[code]`
- Two OpenMP loops use it: `vio.cpp:1604-1606` (photometric update) and `voxel_map.cpp:674-676` (LiDAR point-to-plane
  update), each calling `omp_set_num_threads(MP_PROC_NUM)`. That call overrides the `OMP_NUM_THREADS=2` that
  `t35d_probe_container.sh` sets. `[code]`
- So the mapper compute is at most 4 OpenMP threads, if the build saw more than 4 CPUs. The build log line "Multithreading enabled.
  Cores: N" was not found in the saved logs, so the compiled value is `[unverified]`. Docker `--cpus 2` (which the probe
  container uses) is a CPU quota, not a core list, so CMake would likely still have seen all 16 CPUs `[inferred]`.
- The container is capped at `--cpus 2` (`t35d_probe_container.sh:13`): 4 threads would share 2 CPUs of quota. `[code]`, effect `[inferred]`.
  Other threads (ROS executor, camera parameter node, rosbag play) are not counted here.

- No frame took 100 ms or more. The LiDAR period is 100 ms (10 Hz), so the worst printed LIO or VIO stage used
  at most 95% of it by itself, and the means are about 10 to 18% of it. LIO and VIO tables are separate; adding them is an upper
  bound on one frame's algorithm time `[inferred]`, it ignores callbacks, image handling and the Docker CPU quota.
- Frame counts (up to 16528) are larger than the bags (the `spin-corrected` bag holds 408 LiDAR messages): the mapper logs cover
  whole sessions including stationary initialisation and stalls. `[inferred]`
- No CPU or GPU usage is recorded anywhere in the T3.5d logs: grep for `%cpu|cpu usage|nvidia|gpu|utilization|pidstat|load average`
  over the attended-session and probe log folders returned nothing outside the mapper's own tables. `[measured]`
