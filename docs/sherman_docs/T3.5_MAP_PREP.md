## First tested change: refuse absent graph before hardware actions

`[code]` `shared/slam_maps.py` requires both readable, nonempty regular files.
`slam_localization.launch.py` calls it before constructing any launch actions and
passes the checked prefix to `map_file_name`. Existing `GAPPLER_MAP_DIR` override
and `completed_map` basename are retained; no maps or directories are created.
Failures report the exact missing/empty/unreadable file.

`[observed]` Four focused tests passed on Mac and box. The real ROS construction
test confirmed missing-map refusal before any Node/IncludeLaunchDescription call.
All three descriptions/includes also constructed with explicit nonempty fake graph
files. Those are construction fixtures, NOT successfully deserialized maps.
No launch actions, sensors, hardware drivers or navigation controllers ran.
Raw results: [map prerequisite evidence](../bench-runs/2026-10-07-sherman-t3.5-map-prerequisites.txt).

## Second tested change: require explicit start pose before hardware actions

`[code]` `shared/slam_maps.py:require_initial_pose` requires `GAPPLER_MAP_START_POSE`
as finite `x,y,theta` (e.g. `export GAPPLER_MAP_START_POSE=0.9,0.5,0.25`).
`slam_localization.launch.py` calls it right after the map gate, before any launch
actions, and passes `{"map_file_name": map_prefix, "map_start_pose": start_pose}`.
Without this, the `map_start_at_dock:false` default would silently localize at the
origin. Launch without the export refuses; this is intentional, not a setup bug.

`[observed]` Six focused tests pass on Mac and box; construction checks confirm
missing-map AND missing-pose refusal before any Node/Include call. The synthetic
persistence bench additionally observes a good post-`/initialpose` pose on the
isolated localizer (error 0.000 m). Causal reseed efficacy remains unproven without
a matched negative control. Raw results: [init-pose evidence](../bench-runs/2026-10-07-sherman-t3.5-init-pose.txt).

## Third tested change: verify the saver manifest before hardware actions

`[code]` `shared/slam_maps.py:require_snapshot_manifest` requires `manifest.json`
in the snapshot directory: valid JSON object, non-empty frame, positive integer
dimensions, finite positive resolution, and matching SHA256 checksums for all four
snapshot files. `slam_localization.launch.py` calls it third, after the file and
pose gates, before any launch actions. A hand-copied or half-written snapshot
without a matching manifest refuses startup instead of loading stale mixtures.

`[observed]` Eight focused tests pass on Mac and box; construction checks confirm
missing-map, missing-pose AND missing-manifest refusal before any Node/Include
call. Raw results: [manifest evidence](../bench-runs/2026-10-07-sherman-t3.5-snapshot-manifest.txt).

## Outstanding

### Readiness-gate proposal, 2026-10-13 (not implemented, no code in this change)

Addresses the two recorded holes: nonempty corrupt graphs pass the availability gate
and abort the localizer with `std::length_error` (see [persistence](T3.5_SLAM_PERSISTENCE.md)),
and file checks cannot prevent files changing between construction and loading.

- **G1 (exists):** file/pose/manifest gates at launch construction. Keep as-is.
- **G2 (proposed dry-load):** explicitly select a trusted owned snapshot and use only
  the localizer plus isolated, map-compatible scan/TF input on empty domain 127,
  localhost-only. Set the localization YAML, staged `map_file_name` and finite
  `map_start_pose`; never use a full hardware launch. Bound startup/runtime,
  clean only owned process groups, and require a usable loaded map **and fresh
  pose/TF**, not just a service reply. The asymmetric-room generator cannot
  validate a physical lab snapshot; suitable recorded input remains required.
- **G3 (proposed staging/re-verify):** capture one manifest and copy its four
  payloads into independent private session files, checking hashes of the bytes
  actually copied. Do not use symlinks/hardlinks. Dry-load and later attended
  reload must use that same staged candidate. Recheck staged hashes before/after
  and exclude concurrent writers. This detects lasting changes, not transient
  change-and-restore by another same-user writer; immutability is not enforced.
- **G4 (proposed corrupt-graph procedure):** never auto-retry a malformed graph on the
  hardware domain. Stop, inspect the preserved crash log, rebuild the snapshot from a fresh
  mapping session. No vendor fix claimed.

G2–G4 need a maintained bench plus an attended dry run before they gate anything.

The parallel readiness audit calls for two focused fixture additions before
claiming startup/reseed efficacy: a fresh localizer using nonempty automatic
`map_file_name`/nonzero `map_start_pose` with **no deserialize request**, and
matched fresh-process reseed/control trials with identical scans/continuous
odometry where only the correct `/initialpose` seed changes. If the control
also recovers, reseed efficacy is inconclusive, not PASS. Require fresh pose/TF
alongside the map. The existing persistence bench now contains these two fresh
automatic-startup/control trials, with localization YAML and fixed odometry,
but their runtime assertions are **unverified**: lab access failed before any
test could start. See [test preparation](../bench-runs/2026-10-13-sherman-t3.5-startup-prep.txt).
Local fixture checks do not close the parameter-startup/reseed evidence gaps.
