# T3.5d attended live mapping: result, 2026-10-20

Status: stationary initialisation and hand-driven mapping done on the lab box with live sensors.
Sherman judged the recorded map coherent except for the transparent and mirror section. The spin
test is inconclusive for the sign question. T3.5d marked DONE by Sherman on 2026-10-20. Not pushed. T3.5e and T3.5f are not started.

## How it ran

- Mapper: the T3.5c combined image `ac276ad7` in a container on the host network (`--network host
  --ipc host`, no devices, no extra capabilities, ROS domain 174, localhost only). Drivers ran
  natively on the box: Livox Mid-360 and the serial-pinned D455 at 640x480x30. No native FAST-LIVO2
  build exists on the box (Sophus and vikit are absent), so this route replaced the runbook's
  native overlay. No map-to-odom bridge was run (it does not exist, it belongs to T3.5f).
- Probe scripts `tools/fastlivo/live/` (commits `b74fe35`, `e8eef42`, `2570d79`). A sensor-free dry
  run first: stationary02 played from the host into the container reproduced B2 (lidar 747, image
  2,179, diagnostic rows 1,482, 118 zero-point coloured frames at the same positions, 1,303
  retrievals). It was not bit-identical: 418 of 1,482 coloured counts differed (median 0.1%).
- Session directory `~/rcp-Gappler/log/t59-fastlivo/log/t35d-attended-20261020.raLTgE` (74 files,
  7.0 GB). Manifest `EVIDENCE_t35d-attended-session-20261020.sha256` (SHA `7dd6dadc...`).

- Restart after the stall (below), `init2`: 12 samples over 30 s, max displacement 5.7 mm, taken

## Stall event (recorded, not hidden)

At 13:48:19 to 13:48:51 the box NIC `enp2s0` lost carrier several times and downshifted to 100
Mb/s while the Orin cable was being unplugged. The mapper logged IMU time jumps of 8.1 s and 15.1 s
and 9 `Received an empty point cloud` errors, then reset. After that the link was stable (carrier
count 24, unchanged). The stationary evidence from 13:45 predates the event. See
`init/STALL_EVENT_20261020.txt`.

## Spin test: inconclusive for the sign

Two runs, one slow turn each (-358 and -360 degrees), the second with the pre-correction
`extrinsic_T` as a labelled contrast config (`live/config/t35d_contrast_precorrection_visual.yaml`,
differs only in that line). A fit of drift plus a body-fixed rotating offset gives the effective IMU
position in the base frame: run 1 (0.19 to 0.20, 0.07 to 0.08), run 2 (0.172 to 0.179, 0.03 to
0.04). Run 2 minus run 1 is (-0.018, -0.042) m against 2 x T_corrected = (-0.022, -0.047) m, within
about 5 mm. Reading `[inferred]`: the mapper places the LiDAR by registration and reports the IMU
pose as that minus the extrinsic it was given, so the reported pose follows the config whichever
sign is true. The runbook's "holds still / walks a circle" table gives "inconclusive". The sign
stays documented (vendor manual and code reading), not measured. A common +5 cm y offset in both
runs is the hand pivot or the eye-measured mount y.

For T3.5f: derive the bridge constant from the same extrinsic the mapper ran with (equivalently
base = LiDAR pose minus the mount) and the sign question does not move the base pose.

## Shutdown

Mapper stops: 2 of 4 printed `terminate called ... RCLError: could not create publisher: rcl
node's context is invalid` (SIGABRT, no core on the host); the other 2 ended after the SIGINT line
with no abort text and unknown exit codes. Drivers stopped within 2 s with no crash text, exit codes
not captured. ROS daemon for domain 174 stopped. Nothing of ours left running.

## Not proven

No absolute accuracy or calibration. Mount rotation is eye-estimated zeros. The extrinsic sign is
not measured. No saved map, no localisation (T3.5e), no Nav2 wiring or transform tolerance (T3.5f).
Live results are not reproducible bit for bit. The box hung silently once (06:19, 20 Oct) and needed
a power cycle; the cause is unknown.
