# T3.5 FAST-LIVO2 offline replay

2026-10-15, `t3.5-launch-prep` (isolated lab worktree
`~/rcp-Gappler/log/t59-fastlivo`, branch formerly `t5.9-fastlivo-feasibility`).
FAST-LIVO2 is the T3.5 implementation by Sherman's 2026-10-15 decision; the
SLAM Toolbox line is held as reference. No robot hardware was touched in any step below: no drivers launched, no
sensors commanded, no motion. The only live hardware contact was read-only
(USB listing, MID-360 ping at `192.168.1.3`, process inspection).

## What was built

U-AMC ROS 2 fork of FAST-LIVO2, pinned `a09599a288c56b832114d7ad9e898248a4111d9e`,
with exact dependency pins (Vikit `6f213c7`, Livox driver2 `13eb05e` = v1.2.6,
SDK2 `f5d9375` = v1.3.1, modern apt Sophus — the old `a621ff` source recipe is
API-incompatible). Built inside an ordinary Docker container (8 GiB, 2 CPUs,
no privileges/mounts/devices, bridge network for apt/git only) and committed
as `t59-fast-livo2:experimental`. Compile-only checks passed (package,
executable, shared-library resolution; no ROS nodes started).

## What was replayed

Authors' `Bright_Screen_Wall.bag` (360 MiB, 66.7 s: 667 LiDAR, 13515 IMU,
668 images) converted ROS 1 → ROS 2 with a validated single-write converter:
all **14,850 messages** byte/timestamp-verified, original checksums unchanged.
Images pre-decoded to raw bgr8 offline (`Bright_Screen_Wall_raw`, digest
`ae8be298…`, all messages reverified) after the republisher findings below.

Best full run: player EOF exit 0, clock covering metadata bounds, **664 odom,
663 valid clouds (9.19 M points), 600 images, 0 invalid**, 662 positive
visual-map retrievals, matched startup QoS, no container-main-process OOM.
This establishes finite smoke-test outputs, not accuracy or complete estimator
consumption. Callback-log reconciliation later found ten initial IMU messages
unlogged in this normal run. Verdict remains FAIL.

## Findings

1. **Wrong image-topic remap (fixed, runtime-confirmed).** The republisher
   subscribes to `/in/compressed`, which `in:=/left_camera/image` does not
   match. Corrected to `in/compressed:=/left_camera/image/compressed`; the
   next paused diagnostic showed the expected subscription.
2. **Republisher shutdown segfault (bypassed, not fixed).** GDB backtrace:
   `rclcpp::CallbackGroup::~CallbackGroup()` during SIGINT teardown, with
   zero frames played. Root cause is not established; the republisher no longer runs.
3. **Empty LIO clouds are source-observed behavior (gate corrected 2026-10-16).**
   In LIVO mode `publish_frame_world` fills the message only on the VIO
   branch, so all ~665 LIO frames emit default-empty clouds. The harness
   counts them as expected heartbeats, not defects; 663 VIO clouds carried
   the 9.19 M points with zero invalid outputs.
4. **Mapper teardown segfault (open).** `fastlivo_mapping` exits -11 on
   SIGINT after a full data run, but exits 0 with no data (mapper-only
   probe: camera/mapper/player all 0). GDB backtrace: `free()` inside a
   `shared_ptr<PointCloudXYZINormal>` dispose under `~LIVMapper()`.
   This locates the failure but does not establish double-free, allocator
   mismatch, or processed data as a necessary precondition.
5. **Camera lookup probe differed with clock available.** The mapper threw `Camera model not
   correctly specified` in a clock-free probe; with the paused player's
   clock it loads all 12 parameters exactly.
6. **Mixed-binary ASan startup (2026-10-16).** The player initially aborted
   because ASan was not loaded first. Preloading only `libasan.so.6` then hung
   Python in an unresolved `real___cxa_throw` interceptor. Preloading ASan
   followed by `libstdc++.so.6` completed the paused diagnostic. This was a
   diagnostic-environment workaround, not a mapper fix. The stopped build's
   actual flags confirm mapper instrumentation but not Vikit instrumentation.

## 2026-10-16 patched ASan run: guard holds, destructor diagnosed

- `[observed]` Patched ASan image `56f183c4` (guard string verified in binary),
  rate-0.2 run `t59-replay-20261016T083645Z-421664`: player EOF, 120 s drain
  timeout with 6,750 IMU callbacks still unlogged (ASan slowness, unchanged).
   **No `vio.cpp` report in the processed subset; the backlog prevents a
   full-recording guard-coverage claim.**
  331 valid clouds (4.57 M points), 331 visual retrievals, 0 invalid outputs.
- `[observed]` At requested SIGINT cleanup, ASan reported `heap-buffer-overflow`,
  8-byte READ in `Eigen::handmade_aligned_free`, via
  `pcl::PointCloud<PointXYZINormal>::~PointCloud` → shared-pointer dispose →
  `~LIVMapper()` → `main` — the exact GDB crash site. The 330,912-byte buffer
  (6,894 points) was raw-`malloc`'d inside uninstrumented `libpcl_filters`
  (the fork's only INormal filter call is `VoxelGrid::filter(*feats_down_body)`
  at pinned `LIVMapper.cpp:531-532`); Eigen's aligned free read an 8-byte
  header that was never written.
- `[code]` Root cause (Eigen 3.4.0 `Memory.h:23-58`): with 16-byte max
  alignment, `aligned_allocator` uses the plain malloc/free pair (as in
  Ubuntu's prebuilt PCL); with 32-byte alignment it uses the handmade header
  pair. The fork's x86 `-march=native` enables AVX2 on this box (verified in
  `/proc/cpuinfo`), raising our alignment to 32 bytes while system PCL stays
  at 16. Allocator mismatch on every VoxelGrid output buffer; the normal-build
  `free()` segfault follows. Upstream (no `march=native`) never hits this.
- `[code]` Fix staged in recipe (10/10 pure tests both sides, real-file dry
  run on both pinned CMakeLists): `patch_cmake.py` drops `-march=native` from
  FAST-LIVO2 x86 Release flags (keeping `-O3 -mtune=native -funroll-loops`)
  and Vikit x86 flags (keeping the SSE baseline); fail-closed exact-once
  replacements, re-patch refused. Vikit is included because its Eigen objects
  cross into the mapper. Consequence: a clean ASan full replay stays
  unachievable with prebuilt PCL (ASan forces the handmade pair via
  `__SANITIZE_ADDRESS__`); ASan remains the bug-finder, normal replay is the
  acceptance gate.

## Residuals

- Eigen/PCL allocator mismatch is a supported diagnosis, not uniquely isolated
  causality (ASan also changes allocator selection). The patched normal build
  shut down cleanly in the 2026-10-17 PASS replay; this is not a universal fix proof.
  Invalid-context shutdown exception seen only in slow ASan runs with large
  backlogs; not observed in normal replays.
- Vikit overwrites sanitizer/debug flags. Mixed instrumentation limits
  coverage; it does not itself identify the cause of either crash. No clean
  ASan run would establish absence of memory defects or prove a threading race.
- LiDAR answers ping but no driver has published clouds/IMU in this session;
  D455 present on USB but not live-checked; T5.5 calibration not done.
- No trajectory-accuracy claim (no ground truth), no whole-bag output
  reconciliation beyond the smoke thresholds, no Nav2/TF integration.
