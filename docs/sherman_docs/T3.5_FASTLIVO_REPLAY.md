# T3.5 FAST-LIVO2 offline replay

2026-10-15, `t3.5-launch-prep` (isolated lab worktree
`~/rcp-Gappler/log/t59-fastlivo`, branch formerly `t5.9-fastlivo-feasibility`).
FAST-LIVO2 is the T3.5 implementation by Sherman's 2026-10-15 decision; the
SLAM Toolbox line is held as reference. No robot hardware was touched in any step below: no drivers launched, no
sensors commanded, no motion. The only live hardware contact was read-only
(USB listing, MID-360 ping at `192.168.1.3`, process inspection).

## What was built

U-AMC ROS 2 fork of FAST-LIVO2, pinned `a09599a288c56b832114d7ad9e898248a4111d9e`,
with exact dependency pins (Vikit `6f213c7`, Livox driver2 `13eb05e` = v1.2.6,
SDK2 `f5d9375` = v1.3.1, modern apt Sophus — the old `a621ff` source recipe is
API-incompatible). Built inside an ordinary Docker container (8 GiB, 2 CPUs,
no privileges/mounts/devices, bridge network for apt/git only) and committed
as `t59-fast-livo2:experimental`. Compile-only checks passed (package,
executable, shared-library resolution; no ROS nodes started).

## What was replayed

Authors' `Bright_Screen_Wall.bag` (360 MiB, 66.7 s: 667 LiDAR, 13515 IMU,
668 images) converted ROS 1 → ROS 2 with a validated single-write converter:
all **14,850 messages** byte/timestamp-verified, original checksums unchanged.
Images pre-decoded to raw bgr8 offline (`Bright_Screen_Wall_raw`, digest
`ae8be298…`, all messages reverified) after the republisher findings below.

Best full run: player EOF exit 0, clock covering metadata bounds, **664 odom,
663 valid clouds (9.19 M points), 600 images, 0 invalid**, 662 positive
visual-map retrievals, matched QoS throughout, no OOM. The estimator core
works on public data. Verdict still FAIL on the one item below.

## Findings

1. **Wrong image-topic remap (fixed, runtime-confirmed).** The republisher
   subscribes to `/in/compressed`, which `in:=/left_camera/image` does not
   match. Corrected to `in/compressed:=/left_camera/image/compressed`; the
   next paused diagnostic showed the expected subscription.
2. **Republisher shutdown segfault (bypassed, not fixed).** GDB backtrace:
   `rclcpp::CallbackGroup::~CallbackGroup()` during SIGINT teardown, with
   zero frames played. Upstream ROS bug; the republisher no longer runs.
3. **Empty LIO clouds are upstream design (gate corrected 2026-10-16).**
   In LIVO mode `publish_frame_world` fills the message only on the VIO
   branch, so all ~665 LIO frames emit default-empty clouds. The harness
   counts them as expected heartbeats, not defects; 663 VIO clouds carried
   the 9.19 M points with zero invalid outputs.
4. **Mapper teardown segfault (open).** `fastlivo_mapping` exits -11 on
   SIGINT after a full data run, but exits 0 with no data (mapper-only
   probe: camera/mapper/player all 0). GDB backtrace: `free()` inside a
   `shared_ptr<PointCloudXYZINormal>` dispose under `~LIVMapper()`.
   Heap bug needing processed state; AddressSanitizer rebuild staged next.
5. **Camera lookup needs clock.** The mapper threw `Camera model not
   correctly specified` in a clock-free probe; with the paused player's
   clock it loads all 12 parameters exactly.
6. **ASan needs preload for mixed binaries (2026-10-16).** The instrumented
   replay aborted at startup: uninstrumented helpers (bag player) need
   `LD_PRELOAD=libasan.so.6` via `T35_LD_PRELOAD`, unset for normal images.

## Residuals

- 2026-10-16: ASan image `t35-fastlivo-asan:experimental` built with linkage
  verified (`libasan.so.6`); first instrumented replay aborted on the missing
  preload, now corrected via `T35_LD_PRELOAD`. ASan backtrace run, minimal
  fork patch, normal rebuild and PASS rerun still owed.
- LiDAR answers ping but no driver has published clouds/IMU in this session;
  D455 present on USB but not live-checked; T5.5 calibration not done.
- No trajectory-accuracy claim (no ground truth), no whole-bag output
  reconciliation beyond the smoke thresholds, no Nav2/TF integration.
