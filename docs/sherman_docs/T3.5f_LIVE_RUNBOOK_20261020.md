# T3.5f live runbook: option 2 chain, SLAM Toolbox mapping from FAST-LIVO2 poses

Prepared 2026-10-20, revised 2026-10-21 for Sherman's lab session. Protocol only: nothing here has been run live, no hardware touched in preparing it,
no live result is claimed. Operator: Sherman, attended. Nobody sends a motion command. The base is pushed by hand. Never publish `/cmd_vel`,
`/goal_pose` or an arm topic. Tags: `[measured]` seen on this branch offline or on the box without hardware, `[code]` read from source,
`[unverified]` expected but not yet seen live.

What this session does: the mapper (FAST-LIVO2, in its container) gives the pose, a small bridge turns it into `odom -> robot_base_link`, SLAM Toolbox builds a 2D
`/map` from that pose with its own scan matching and loop closing OFF (the T3.5e diagnostics: the scan-matched map warped by up to 0.5 m, the poses-only map agreed
with the 3D cloud). Nav2 is not started. The base driver is not started while pushing.

Known limit, so nobody tries it live: SLAM Toolbox cannot reload a graph saved in this mode (it segfaults on the graph, T3.5e). This session maps only; it does not
test a reload.

Mapper config: the corrected visual and camera YAML are staged in `docs/sherman_docs/tools/fastlivo/live/config` (`t35c_stationary02_20261019_visual.yaml`,
`t35c_stationary02_20261019_camera.yaml`, byte-identical to `replay/config/`, extrinsic `[-0.011, -0.02329, 0.04412]`; a test pins both). Never use the pre-correction
T3.5d contrast file for a live run (it is in the same folder, kept as evidence). `[code]`

measure the centre-to-centre distances AB, AC and BC, and the heading of the arms at B and C relative to A's arm (use a protractor, or lay the tape along A's arm and measure the offset

AB_m=
AC_m=
BC_m=
B_heading_deg=
C_heading_deg=
measurement_error_m=
notes=

### Check D1: the numbers close

python3 -c "

## F. Push drive (hands on the base, no driver running)

- Walking pace or slower, smooth starts and stops. No wheel spin (nothing drives the wheels).
- Gentle turns: wide arcs, a full turn takes 10 s or more (T3.5d: slow turn about 360 deg). No snap rotations.
- Stay in LiDAR view of walls and furniture. Avoid long glass or mirror runs (T3.5d: those mapped badly).
- Keep a loop short: about 30 m path, farthest point about 3.5 m (T3.5d scale). Do not stop for more than a few seconds with people crossing the LiDAR view.
- Watch RViz if you have the desktop: if the 2D map doubles a wall or the odom jumps, note the time and keep going to the mark. Do not stop to fix it.
- **End exactly on mark A**, same heading as the start. Stand still 10 s.

## J. Not proven by this runbook

Frame ownership and rates are expectations from source and offline tests; nothing here shows Nav2 can follow the resulting `map` frame, or any accuracy beyond the floor-mark readings and one
return to the start. This session does not test a reload: SLAM Toolbox cannot reload a graph saved in this mode, and the T3.5e finding that a poses-only map reloads about 3 times closer to the tape
than a scan-matched one was measured with a separate plain matcher, not with SLAM Toolbox.
