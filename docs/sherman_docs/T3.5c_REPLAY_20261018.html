2. What the failure means

[code + observed] Round B received 2,941 cloud messages: 1,471 default-empty LIO heartbeats (excluded by the existing rule), 419 typed-empty VIO clouds, and 1,051 nonempty clouds with 141,401 finite XYZ points in total. The 419 have width 0, height 1, point_step 32, zero data bytes and fields x/y/z/rgb. They remain invalid under the existing contract; they have not been reclassified as harmless.

[code] publish_frame_world builds coloured clouds only from points projecting into the camera image. Its VIO path converts a typed PCL cloud even when that cloud is empty. Its LIO path in LIVO mode publishes a default message instead. These two source paths explain the different message layouts, but do not prove why so many VIO clouds are empty.

[observed] The visual module created map points but every logged retrieval returned zero. [code] computeJacobianAndUpdateEKF returns immediately when total_points == 0. Thus image publication is not evidence of camera-derived pose corrections. Removing the cloud failure alone would still leave the positive-retrieval requirement unmet.

[code] LIVO synchronisation cuts LiDAR data around camera timestamps and alternates LIO/VIO processing. Our 30 Hz images versus the public bag's approximately 10 Hz images explain different processing cadence; larger counts alone do not establish a defect.

Working control: the earlier public-bag PASS 20261016T175305Z-433728 used the same image ID and recorded 663 positive retrievals, 663 nonempty clouds with 9,182,028 points and zero invalid outputs. Different scene, calibration and sensor configuration mean this is a control, not a one-variable causal experiment.

3. Confirmed source mismatch; run-level cause still unknown

[code] Pinned vio.cpp:228–238 inserts using a floating-point division, subtracts one for negative values, then truncates to integer. Retrieval at vio.cpp:380–398 floors first, then subtracts one again for negative bins. Its raycast path repeats the latter rule, although raycasting is disabled in this config.

The example uses 0.5 m voxels and non-boundary values. A point stored in one spatial bin can be searched for in its neighbour. This is a deterministic arithmetic mismatch, not proof that correcting it would make this recording pass.

[exploratory proxy] Read-only sampling of raw scans 10,106,211,317,422,528,633,739 using nearest logged poses and a 20 px image border found 87–176 projected points per scan, occupying two insertion bins. Each sample retained one bin reachable by current raw-cloud lookup; 50–72 projected points per sample had differing self insertion/lookup keys. The proxy does not reconstruct downsampling, deskew, plane normals, the actual visual map, exact consumer border/distortion semantics or photometric filtering. It therefore cannot identify the rejecting stage.

The prior projection report already found only 0.16–0.23 m near-surface returns in view on this bag. There is no evidence here that stationary data inherently forbids matching, or that the nominal extrinsic is correct or incorrect.

[code] A second concrete source defect explains how invalid visual seeds can enter: generateVisualMapPoints (vio.cpp:813–900) projects points and checks image bounds, but does not require positive camera depth before selecting or storing them. This omission occurs in both candidate sources and the final insertion path. Retrieval correctly rejects negative-depth points at vio.cpp:461–463. Frame::w2c calls the pinned Vikit pinhole projection, which divides x/y by z without a visibility test.

u = fx * X/Z + cx;  v = fy * Y/Z + cy
(X,Y,Z) = (0,0,+1) → (cx,cy): in front
(X,Y,Z) = (0,0,−1) → (cx,cy): behind, but same pixel!

Being inside the image rectangle is therefore not sufficient to be visible. [observed] Every candidate examined in this replay failed that sign test. [inferred] The unchecked seeding path is a supported mechanism for the bad candidates; the counters do not log each point's sign at insertion or explain why no usable front-facing seed survives. The scene's sparse near-only overlap remains a separate limitation. This is not evidence to reverse or tune the extrinsic.
