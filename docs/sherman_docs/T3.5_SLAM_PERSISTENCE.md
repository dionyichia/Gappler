# T3.5 synthetic SLAM persistence

2026-10-07, `t3.5-launch-prep`. This is the first before-visit save/reload experiment,
not completion of the saving procedure, deployment or physical localization.

## What ran

`bench/slam_persistence.sh` runs installed SLAM Toolbox 2.6.10 on empty domain 127,
localhost-only. It starts only the test publisher/recorders, mapper/localizer and
image saver. Scan/map/pose and TF topics use `/t35_slam/`; frames are test-specific.
No camera, LiDAR/base/arm driver, Nav2 controller or wheel command is involved.

The fixture is an asymmetric room with an internal wall segment. Rays intersect
the known segments to produce 720 scan ranges. Exact odometry accompanies 41 poses
around a 1 m square; six scans per pose at roughly 10 Hz. Candidate mapping YAML is
loaded with isolated frame/topic overrides, faster map publication and wall-clock time.
This exercises the installed implementation, not full candidate launch actions.

## Sequence and evidence

1. Mapping receives synthetic scans/TF and publishes multiple poses and a map.
2. `/slam_toolbox/serialize_map` saves graph/data; result and nonempty files checked.
3. Installed Nav2 map saver exports YAML/image using an argv list and explicit private
   map topic. Filename contains spaces. YAML image reference/resolution checked.
4. Mapper stops; test waits until its node leaves discovery before restarting.
5. Fresh localizer receives missing and malformed graph requests (details below).
6. Fresh/recovered localizer loads the valid graph using `LOCALIZE_AT_POSE`.
7. Loaded map metadata and every raster cell match the original mapping map exactly.
8. Three known poses are checked using current scan timestamps, with odometry biased
   by (+0.4 m, -0.3 m, +0.1 rad). Position/heading acceptance is 0.15 m / 0.10 rad.

`[observed]` Loaded map was 160 × 120 cells with free and occupied cells. Three errors
were approximately 0.000–0.001 m and 0.001 rad. These are ideal synthetic measurements
with a nearby initial estimate, NOT expected real-room accuracy or global recovery.
After cleanup, domain 127 was empty. Temporary graph/images were removed; logs retained.
[Raw results and source hashes](../bench-runs/2026-10-07-sherman-t3.5-slam-persistence.txt).
Five pure tests and available Mac quick checks passed. Review's interrupted-startup
cleanup gap was fixed; a real harmless child is terminated in the regression test.
Follow-up review confirmed that blocker resolved.

## Important failure findings

- Installed `DeserializePoseGraph` has an empty response. Missing files produce a
  reply but no usable map. A reply is not load-success evidence.
- The malformed graph fixture aborts the installed localizer with `std::length_error`.
  This is recorded as an observed limitation, NOT safe rejection or a fixed vendor bug.
  The test preserves the crash log, cleans up and restarts before the valid-load case.
- Upstream 2.6.10 image-save service builds an unquoted shell command. The bench uses
  direct argv to `map_saver_cli` instead, successfully handling spaces without modifying
  vendor code. Existing candidate mapping autosave has not yet been replaced.
- An interim restart request timed out while stopped-node discovery was stale. The
  maintained test now requires the old node to depart before constructing its replacement.

The file-availability gate added earlier does not detect nonempty corrupt graphs.
Before hardware startup, a stronger localization-readiness procedure is still required.

## Re-run

From an approved candidate checkout, with no competing bench/CI job:

```bash
python3 bench/test_slam_fixture.py
bash bench/slam_persistence.sh
```

Runs serially with the keyboard/cloud benches: all reserve domain 127.
Logs: `log/t35-slam-mapping.log`, `log/t35-slam-localization.log`,
`log/t35-slam-corrupt-load.log`, `log/t35-slam-image-save.log`.
Exit 0 means valid synthetic round trip verified; it does NOT mean corrupt-file
handling is safe. Exit 1 is failure/refusal, 3 is unavailable dependency SKIPPED.
