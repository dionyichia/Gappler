## Findings and remaining limits

1. Saved `analyze_proof3_ros.py` still prints incorrect offset units (ns labelled
   us, ns/1000 labelled ms), labels a mean as median, checks only sampled point
   validity and emits `ANALYSIS_OK` without acceptance assertions. It is not a
   reliable pass/fail gate. The full streaming audit above supersedes those claims.
2. First-message proximity is not sensor synchronisation. Reviewed driver source
   `src/comm/pub_handler.cpp:265–276` uses packet timestamps for PTP/GPS, but
   otherwise substitutes host time. The capture does not establish which branch
   ran. Host clock discipline, camera timestamp mapping and physical delay remain
   unproven; do not infer correction offsets from these receipt lags.
3. Livox binary/config hashes still match the recorded values. Runtime parameter
   dumps, loaded-library manifests and exact binary-to-source provenance were
   not fully captured; current files are not proof of every historical runtime
   setting. Full precision camera calibration remains in the original bag.
4. No VIO ASan report during a partial-backlog run does not prove full-bag guard
   coverage. Eigen/PCL mismatch is a supported diagnosis, not uniquely isolated
   causality: ASan also changes allocation strategy. Normal clean shutdown is
   observed, not a universal proof that all memory defects are fixed.
5. Fix/recipe/harness implementations remain scratch tooling outside tracked
   runtime code. Documentation commits alone do not make the build reproducible.

Shutdown check: no matching capture processes reported; only `gh-runner` tmux
session remains. Bags were opened read-only. No hardware restarted.
