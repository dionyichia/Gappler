# T3.5 explicit map snapshots

2026-10-07, `t3.5-launch-prep`. Candidate source only; not installed/deployed.
This implements the explicit saving step after the synthetic persistence experiment.

## Purpose and operation

`nav/robot_slam/scripts/save_slam_map.py` saves `completed_map.posegraph/.data`
and `current_map.yaml/.pgm` into a new `session-<UTC>-<id>` directory.
There is no overwrite option. Historical maps are never selected automatically.

The operator must first stop movement command sources and establish physical
stationarity, then acknowledge `--stationary`. This is an acknowledgment, not a
measurement or brake. The saver itself never sends wheel commands or enables drivers.

1. Verify mapper mode, pause state, map update interval and exact image-topic match.
2. Subscribe to the map: SLAM skips raster updates with no subscribers.
3. Pause new SLAM measurements if not already paused; require multiple map
   publications including one after a full raster interval. **This does not stop wheels.**
4. Serialize graph/data and check the service result; export the image through
   direct argv `map_saver_cli`, avoiding the upstream unquoted shell service.
5. Check graph files, relative image reference, resolution, origin, PGM dimensions
   and full raster length. Write file checksums and source map metadata to manifest.
6. Exclusively create a new destination and move payload files, manifest last.
   This is not an atomic directory transaction: a filesystem error may leave an
   incomplete destination. No success is reported; never use an incomplete snapshot.
7. Restore the original measurement-pause state, then print `SAVED_SNAPSHOT=...`.

Only one mapper operator/saver may run at a time. Pause is a toggle service; this
tool is not a concurrency lock. Failed or timed-out service requests can have
completed remotely. Read pause state/logs and do not blindly repeat the save.
Failure artifacts are retained for diagnosis, not automatically deleted.

## Operator command, after deployment/attended mapping review

From the approved checkout root, in the mapper's ROS environment/domain:

```bash
source nav/nav_env.sh
python3 nav/robot_slam/scripts/save_slam_map.py \
  --output-root "$(python3 -c 'from gappler_common import path; print(path("map_dir"))')" \
  --stationary
```

Defaults target the root `/slam_toolbox` node and `/map`. If namespaced, explicitly
pass `--namespace` and `--map-topic` matching the mapper. Never switch to domain127
for a lab mapper merely because the software bench uses it.

Expected successful output: one `SAVED_SNAPSHOT=` line giving the new directory,
exit0 and mapping restored to its original pause state. It does not establish
physical map quality. On failure, inspect errors, retained files and pause state.
Use the printed directory as `GAPPLER_MAP_DIR` for candidate localization, whose
loader expects `completed_map` within it. This is NOT permission to execute the
full hardware-facing localization launch before readiness gates are reviewed.

## Verification

`bench/test_map_saver.py` covers no stationary acknowledgment, exclusive publication,
overwrite refusal, malformed image references/raster and repeated-signal child cleanup.
PyYAML-dependent validation is explicitly skipped on the Mac where unavailable;
all five tests run on the box. No dependency was installed on the Mac.

The maintained synthetic SLAM bench runs the actual saver in a directory with
spaces. It removes pre-existing map subscribers and advances the graph, checks the
saved raster timestamp against new scans, reloads the owned graph and compares the
exact occupancy raster. Normal completion and SIGINT/SIGTERM after pausing restore
mapping, proven by pause-state reads and poses matching fresh scan timestamps.
Localization mode is refused before output directory creation.
Results/source hashes: [owned saver evidence](../bench-runs/2026-10-07-sherman-t3.5-owned-map-saver.txt).
Five box tests passed; Mac ran four with one explicit PyYAML skip. Available Mac
quick checks passed; read-only follow-up review confirmed reported blockers fixed.

Packaging declares existing ROS/PyYAML runtime dependencies and installs the script
as a robot_slam executable. Build/install itself has not been run in this change.

## Limits and next work

Existing mapping image autosave is unchanged; this explicit snapshot is the graph
handoff. Automatic graph snapshots are not implemented. File checks do not certify
graph compatibility or all image pixel semantics. Pause restoration can fail if
the mapper disappears; operator intervention is then required. SIGKILL cannot run
cleanup. Concurrent operators and hardware faults are not covered.

Corrupt graph bytes still abort the installed localizer. Initialization/readiness
gates and minimal manual-driving runbook remain before-visit work. No full launches,
hardware drivers/controllers, installed-overlay update, historical map load or
physical acceptance. T3.4/T3.5 remain PROGRESS; teammate coordination pending.
